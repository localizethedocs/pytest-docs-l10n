py.test 2.0.0：a斷言++、單元測試++、報告++、設定++、文件++¶

歡迎使用 pytest-2.0.0，這是快速且方便的 Python 測試工具「py.test」的重大新版本。新版本包含許多新功能和改進，請參閱以下摘要和詳細清單。大量長期棄用的程式碼已被移除，使得新版本更加精簡簡潔。請在此處查看包含範例的新文件：

http://pytest.org/en/stable/index.html

關於打包的說明：pytest 曾經是 py 發行版的一部分，直到 py-1.3.4 版本才被包含在內，但現在情況已經改變：pytest-2.0.0 只包含與 py.test 相關的程式碼，並且預計會向後相容現有的測試程式碼。如果您想安裝 pytest，只需輸入以下命令之一:

pip install -U pytest
easy_install -U pytest

非常感謝所有報告問題、提出疑問或投訴的人。特別感謝 Floris Bruynooghe 和 Ronny Pfannschmidt 出色的代碼貢獻，以及其他許多人的回饋和幫助。

此致，霍爾格·克雷克爾

新功能¶

  • 透過 Python 解釋器和從 Python 發起的新呼叫:

    python -m pytest # 適用於所有 Python 版本 >= 2.5

    或從 Python 程式:

    導入 pytest ； pytest.main（參數列表，外掛程式列表）

    詳情請參閱 http://pytest.org/en/stable/how-to/usage.html。

  • 在比較列表、序列或字串時，斷言表達式中會提供新的、更好的報告資訊。

    請參閱 http://pytest.org/en/stable/how-to/assert.html#newreport

  • 例如，透過 ini 檔案（可識別 setup.cfg 或 tox.ini）進行新配置，例如:

    [pytest]

norecursedirs = .hg data* # 永遠不要在這樣的目錄中遞歸

addopts = -x --pyargs # 預設新增這些命令列選項

    請參閱 http://pytest.org/en/stable/reference/customize.html

  • 改進了對標準單元測試的支援。一般來說，py.test 現在應該能夠更好地運行自訂的 unittest.TestCases，例如 Twisted Trial 或基於 Django 的 TestCases。此外，您現在可以使用 py.test:: 執行已安裝的 『unittest』 套件的測試:

    py.test --pyargs unittest

  • 新增“-q”選項，可減少輸出詳細信息，並列印更像 nose/unittest 風格的“點”輸出。

  • many many more detailed improvements details

修復¶

  • 修復問題 - 引入 py.test.set_trace()，以便在測試運行時透過 PDB 追蹤執行情況，即使捕獲正在進行中。

  • 修復問題 - 使報告對測試開啟檔案描述符 1（stdout）上的檔案更具彈性。

  • 修復問題 - 同級 conftest.py 檔案將無法載入。 （且目錄收集器無法再從目錄的 conftest.py 中進行自訂 - 這需要在至少上一層目錄中進行）。

  • 修復問題 （從命令列參數尋找自訂測試節點）

  • 修復問題：匯入 conftest.py 時捕捉 stdout/stderr

  • 修復錯誤：unittest 收集的函數現在也可以在類別/模組層級應用“pytestmark”

重要提示¶

  • 在 Python 2.0 版本之前，在 Python 程式碼中使用 py.test 的常用方法是先匯入 py，然後使用例如 py.test.raises 來呼叫輔助方法。這種方法仍然有效，目前沒有棄用的計劃。但是，在大多數範例和內部程式碼中，你會發現建議的預設方法是直接匯入 pytest 並呼叫 pytest.raises。

  • pytest 現在會在執行任何測試之前先收集完整的測試套件。這改變了例如 pytest_collectstart/pytest_collectreport 的呼叫語意。某些插件可能需要升級。

  • 這個pytest 套件包含一個 400 行程式碼的 core.py 檔案和大約 20 個內建插件，總計約 5000 行程式碼包括文件字串。公平地說，它還使用了來自“pylib”的通用程式碼以及新的“py”包，以輔助檔案系統和程式碼自省/操作。

（不相容的）移除¶

  • 現在只有在測試執行階段才能使用 py.test.config。

  • 以下功能（大部分已棄用）已移除：

    • 已移除 conftest.py 檔案中 Module/Class/… 集合節點定義的支援。這不會造成任何特殊影響。

    • 移除了對呼叫 1.0 版本之前的集合 API 中的「run()」和「join」函數的支援

    • removed reading option values from conftest.py files or env variables. This can now be done much much better and easier through the ini-file mechanism and the 「addopts」 entry in particular.

    • 已移除測試類別中的“abled”屬性。請使用 skipping 和 pytestmark 機制跳過或使測試類別失敗。

  • py.test.collect.Directory 已不再存在，也無法提供自訂的「Directory」物件。如果您之前使用過此功能但現在不知​​道該如何處理，請與我們聯絡。我們會想辦法解決。

    請注意，pytest_collect_directory() 函數仍然會被調用，但任何返回值都會被忽略。這樣可以保持舊程式碼的正常運行，例如，如果缺少某些依賴項或命令列選項，舊程式碼會在 collect() 函數中使用 py.test.skip() 來防止遞歸遍歷目錄樹。
